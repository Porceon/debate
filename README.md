# 成长辩论擂台 · Growth Debate Arena

> 一个由 AI 智能体团队（6 名成员）跑完三轮的模拟辩论工作区。
> 辩题：**成长的本质是不断得到 / 不断失去** —— 正方「不断得到」，反方「不断失去」。
> 产出：三轮十份公开稿 ＋ 三份裁判判定 ＋ 一份可直接上场的全记录终稿。

---

## 1. 这个项目是什么

`src_debate.txt` 是主办方发下来的原始赛制材料（辩题、题解、环节说明）。围绕它，本仓库做了一件完整的事：

1. 把赛制写成一份**可执行的宪章** `charter.md`（深度硬门槛、反面清单、输出格式、迭代规则）；
2. 建一个**中立军火库** `arsenal/ammo-v1.md`（哲学/心理学/文学/生物学/社会学资源，逐条标注「最利哪一方 + 怎么用才不被打穿」）；
3. 让正反双方各两名辩手按 **R1 立论·质询 → R2 深化·对辩 → R3 总结** 打满三轮，每轮之间由中立裁判判定并点出深度缺口；
4. 由中立方把三轮合稿，压成**严格时长、可直接朗读的上场稿**。

**最终结论（见 `judge/终评.md`）**：三轮均为正方占优，但真正有价值的发现是——双方各自磨出的两把尺（正方「身份≠判据」、反方「算子论证」）**不测同一个东西**，所以这个「本质之争」怎么打都打不完。

## 2. 五分钟上手：我该读哪个文件

| 你是 | 先读 | 用途 | 用时 |
|---|---|---|---|
| 要**上场**的辩手 | `上场定稿-严格时长版.md` | 四份稿均可独立朗读，含应急删减清单 | 30 分钟 |
| **零基础**、完全没打过辩论 | `正方指南-零基础版.md` → `正方上场指南.md` | 术语全翻成大白话 | 1–2 小时 |
| 想理解**论证体系** | `正方作战文件.md` | 理论结构、诘问树、例子库、红线清单 | 1 小时 |
| 要**复盘**三轮交锋 | `终稿-成长辩论全记录.md` 第二、三节 | 逐环节摘要 + 胜负曲线 | 60 分钟 |
| 要当**裁判/评审** | `charter.md` §3、§8 | 只判论证强度，禁止判感染力 | 20 分钟 |
| 想**继续加弹药** | `arsenal/ammo-v1.md` | 先读第 0 节战略，再挑材料 | 按需 |

> 三条铁律（来自 `charter.md`）：
> ① **不许和稀泥**——「成长就是有得有失」直接判负；
> ② **例子不是论证**——一个例子是例子，三个例子是修辞，只有机制才是论证；
> ③ **必须 steel-man**——复述对手最好的版本并正面回应，稻草人一律扣分。

## 4. 赛制与三轮流程

### 赛制环节（`charter.md` §2）

| 环节 | 形式 | 交互要求 |
|---|---|---|
| 立论陈词 | 一辩起立，3–4 分钟 | 无 |
| 四辩质询一辩 | 质询方问、被质询方答，同立 | **短问短答**，忌长问题无交互 |
| 二辩盘问三辩 | 同上 | 同上 |
| 三辩对辩 | 双方三辩同时起立，交替发言 | 单次发言不得过长 |
| 自由辩论 | 本方任一辩手可起立 | 交替、抢点 |
| 小结 | 任一辩手 | 收敛战场 |
| 总结陈词 | 四辩 | 升华 + 收束 |

本擂台的分工：两位「攻防手」兼四辩与三辩，两位「主线」兼一辩与二辩。

### 三轮迭代（`charter.md` §7：**下一轮不得重复上一轮的论证**，原地打转判负）

| 轮次 | 环节 | 裁判判定 |
|---|---|---|
| R1 | 立论 ×2 · 质询 ×2 | 正方窄胜（硬门槛 20:17）——反方把两句最重的话当公理用 |
| R2 | 深化 ×2 · 对辩 ×2 | 正方占优——反方判准的伤在构成上，正方判准的伤在参数上 |
| R3 | 总结 ×2 | **正方胜（窄）**——反方最后把「本质」换成了「定义域」，而定义域比必要条件更弱 |

每份稿必须通过 `charter.md` §3 的**五项硬门槛**：概念操作化 / 判准 / 机制而非修辞 / steel-man / 代价承认。

## 5. 这是怎么被做出来的（智能体团队）

`.agent-teams/growth-debate/` 是 DSH 智能体团队的运行记录，`team.json` 里存着成员、17 个任务的派单与逐条验收结果（criterion / status / evidence / 校验命令）。

| 成员 | 角色 | 持方 |
|---|---|---|
| `arsenal` | 中立思想资源官，供货、概念切分、最终合稿 | 不持方 |
| `aff-lead` | 正方一辩兼二辩：立论、深化、总结 | 得到 |
| `aff-attack` | 正方四辩兼三辩：质询、对辩、自由辩论 | 得到 |
| `neg-lead` | 反方一辩兼二辩：立论、深化、总结 | 失去 |
| `neg-attack` | 反方四辩兼三辩：质询、对辩、自由辩论 | 失去 |
| `adjudicator` | 裁判与进阶教练：每轮判定、点缺口、下轮指令 | 不持方 |

任务依赖链：`t1 弹药库` → `t2–t6 R1` → `t7–t11 R2` → `t12–t14 R3 与终评` → `t15–t17 合稿与上场压缩`，全部 `completed`。

**信息隔离**（宪章 §6）：双方不得阅读对方未定稿，只能读 `rounds/` 里的公开稿与 `judge/` 的判定；裁判可读全部。`inbox/*.jsonl` 中的文件路径与结论均为团队内部通信记录。

## 6. 常用操作

```powershell
# 列出全部稿件
git ls-files

# 只看某一轮的稿子
Get-ChildItem rounds\R1, rounds\R2, rounds\R3 | Select-Object Name

# 统计一份稿的汉字数（不含标点与空白；宪章 §5 的字数门槛按此口径，注意稿末自检表也计入）
$t = Get-Content -Raw -Encoding UTF8 'rounds\R1\aff-立论.md'
([regex]::Matches($t, '[\u4e00-\u9fa5]')).Count

# 扫描违禁的「和稀泥」表述（正常应 0 命中；若命中，请确认它是否出自稿末自检表的"已排除"声明）
Select-String -Path rounds\*\*.md -Pattern '有得有失|辩证来看|既有得到|硬币的两面'
```

新增稿件请严格遵循 `charter.md` §5 的结构：一句话立论 → 定义条款 → 判准 → 论证支柱（3 条，各含主张/机制/证据/对最强反驳的回应）→ 结语钩子 → 预判对手三招 + 反制。字数：立论 900–1400，质询 400–700，总结 700–1100，**宁少勿水**。

## 7. 边界与说明

- 全仓库为中文 Markdown，无构建步骤、无运行时依赖，`git` 即全部工具链。
- `judge/` 的判定只认论证强度；「更有感染力 / 更正能量 / 更符合主流价值观」是明令禁止的判定理由。
- `终稿` 与 `上场定稿` 中的两份上场稿按对立立场编写、互不隶属，**任一方都可取用**；引述对方公开稿是允许的，引述对方未定稿违规。
